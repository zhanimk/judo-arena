## Вывод

Проект имеет рабочую основу полного турнирного приложения. Локально проверяются frontend, API, PostgreSQL, Redis, регистрация, судейство и турнирный движок. Для выбранного пользователем размещения на VPS добавлена отдельная конфигурация с Node SSR и HTTPS reverse proxy. Фактическое размещение на сервере ещё не выполнено: домен и SSH-доступ не предоставлены.

Проверки автоматизированных сценариев не означают построчное доказательство корректности всего проекта и не заменяют репетицию реального турнира. Исходное рабочее дерево уже содержало большой объём незакоммиченных изменений; они сохранены.

## Исправления этого этапа

1. Восстановлены повреждённые зависимости через чистую установку на Node 22.22.1. Наличие папок `node_modules` прежде не гарантировало наличия запускаемого Vitest.
2. `start.sh` проверяет Node, `.env` и Docker Compose, проверяет загрузку ключевых модулей, устанавливает workspace по lock-файлу, ждёт готовности контейнеров, генерирует Prisma Client и применяет миграции. `concurrently --kill-others` завершает второй сервер при выходе первого.
3. Unit-тесты получили отдельные тестовые переменные и запускаются без личного корневого `.env`.
4. Для VPS добавлены `compose.vps.yml`, `deploy/Dockerfile`, `deploy/Caddyfile`, шаблон окружения и [инструкция](VPS.md). БД/Redis не публикуются наружу; доверие forwarded headers ограничено адресом Caddy. Вариант рассчитан на один API.
5. Frontend поддерживает `DEPLOY_TARGET=vps` с Nitro `node-server`. При отсутствии адреса WebSocket клиент использует origin страницы. Это позволяет cookie/API/Socket.IO работать через один HTTPS-домен.
6. PWA ищет static assets и записывает Service Worker в фактическую папку выбранной сборки. Раньше Node-сборка сообщала о 0 precache entries и писала Service Worker в другую папку.
7. Добавлен `create-admin`: создание первого production-администратора без demo seed, отказ от перезаписи существующего пользователя, пароль не передаётся в argv и не печатается. Учтён байтовый предел bcrypt. Создание и повторный отказ проверены на отдельной БД.
8. Выполнена миграция на Zod 4.6.7; старый адаптер `zod-to-json-schema` заменён встроенным генератором JSON Schema для входных данных. Обновлены undici и совместимые транзитивные зависимости. npm audit после исправлений: **0 уязвимостей всего дерева**.
9. Runtime-проверка Docker обнаружила недостаточные права на Prisma schema после копирования папки API с macOS. В финальном образе владельцем файлов API и общих пакетов назначен пользователь `node`; миграции и запуск от этого пользователя проверены.
10. Добавлена проверка VPS-сборки в CI и поддержка её выходной папки в контроле размера JS.

Обнаруженный первоначальным браузерным прогоном сбой повторного входа был связан с тестовым окружением: UI на `localhost`, API на `127.0.0.1` и SameSite cookie. После согласования hostname полный набор прошёл. В VPS-конфигурации все браузерные запросы идут через единый домен.

## Выполненные проверки

- Node **22.22.1**, установка по lock-файлу.
- `npm run verify:local`: линтеры, **350 API-тестов**, API/Web сборки, frontend TypeScript, JS **2492 KB** при лимите 3000 KB.
- `npm run test:db -w api`: **52/52**, включая масштаб турнира; отдельные временные PostgreSQL и Redis.
- Все **33 миграции** применены на пустой тестовой PostgreSQL.
- `npx playwright test`: **47/47** на окончательных зависимостях, включая Zod 4; длительность итогового прогона 1,8 минуты.
- Node SSR VPS-сборка запускается и отвечает **HTTP 200** на главной странице.
- Финальные Docker-образы API и frontend успешно собраны с окончательным lock-файлом. Из API-образа применены миграции к отдельной пустой runtime-БД и создан администратор. Production API запущен с тестовыми локальными адаптерами. Через Caddy получены **HTTP 200** для `/`, `/login`, `/api/tournaments`, `/health`, `/sw.js`; вход администратора — **200**, cookie имеет `Secure`, WebSocket подключается через reverse proxy. Проверка выполнялась по HTTP на loopback; выдача настоящего TLS-сертификата требует целевого домена. Почта/S3 не тестировались настоящими запросами. Service Worker содержит **130 precache entries** вместо прежних 0.
- `docker compose ... config --quiet`: схема VPS валидна; `caddy validate`: `Valid configuration`.
- `bash -n start.sh`, `git diff --check`: успешно.

Внешние письма и реальные платежи при тестировании не отправлялись. Пользовательская БД и production-сервисы не изменялись.
